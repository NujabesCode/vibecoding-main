# 정독 메모 · 설계 리뷰 (step-3)

> ARCHITECTURE.md를 처음부터 끝까지 읽으면서 강사가 적은 메모. 코드는 한 줄도 안 읽었다.

## 읽다가 "어?" 했던 곳

- **"주소의 숫자만 바꾸면 된다"** → 해킹 실습에서 실제로 해봤다. 옆 사람 캐릭터가 내 캐릭터로 바뀌었다. 이건 1순위.
- **"브라우저가 기억하는 건 id뿐"** → 로그인이 없는 게 문제가 아니라, *서버가 요청한 사람을 알 방법이 없는 게* 문제다. 비밀번호까지는 필요 없고, 입장할 때 서버가 추측 불가능한 **토큰**을 발급하면 된다.
- **"디자인을 JSON 하나로 저장"** → 동의. 지금 단계에선 이게 맞다. 대신 서버가 최소한 모양(크기, 필수 키)은 검사해야 한다.
- **"그림 엔진은 리액트 밖 순수 함수"** → 아주 좋다. 메타버스 화면에서 그대로 쓸 수 있다. 이 원칙은 CLAUDE.md에 박는다.
- **"테스트가 하나도 없다"** → 다음 단계부터 기능 하나 = E2E 통과.

## 고칠 것 (우선순위)

| # | 무엇을 | 어떻게 |
|---|---|---|
| 1 | 남의 캐릭터 덮어쓰기 | 입장 시 토큰 발급 → 저장은 `PUT /api/characters/me` + `Authorization: Bearer 토큰` |
| 2 | 디자인 크기·형식 | 서버에서 100KB 제한, JSON 필수 키 검사, 실패하면 400 |
| 3 | 닉네임 | 1~12자, 앞뒤 공백 제거, 실패하면 400 |
| 4 | DB 변경 | 토큰 컬럼은 **새 마이그레이션 파일(V2)** 로 추가. V1은 절대 안 고친다 |

## 앞으로 만들 것의 모양 (문서를 읽고 정한 것)

- 가구 공방: 캐릭터 공방의 엔진(색, 외곽선)을 그대로 재사용
- 맵 에디터: 바닥 타일 + 가구 + 막힌 칸 + 시작 위치. 맵도 JSON 하나로 저장
- 메타버스: WebSocket(STOMP). 위치는 서버 메모리에만, DB에는 안 넣는다
